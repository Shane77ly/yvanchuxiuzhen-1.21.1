# MCreator 生成工程

已核对范围：两个 MCreator 生成的 Minecraft 1.18.2 / Forge 40.1.0 工程（静态核对，未运行）。其他 MCreator 版本的生成模板可能不同，使用前先抽样确认。

## 工程组成

- 来源由生成 Java、资源、`elements/*.mod.json` 编辑器元素和工作区文件组成。Procedure 的 Blockly 图保存在元素文件中。
- 工作区元素带 `locked_code` 标记时，该元素的 Java 已由人工锁定，生成器不再覆盖；以 Java 为准，元素图只作参考。
- Blockly 中挂在 `event_trigger` 根块下的子树为已连接部分；其他顶层块为游离块，不进入生成 Java。已核对工程中，已连接子树的过程调用集合与生成 Java 全部一致。游离块里的检查（例如等级门槛）不会执行，恢复它属于行为调整。调用集合一致不证明条件、参数和执行次序一致。
- 额外依赖可能只在 `mcreator.gradle` 中声明（例如 GeckoLib），需单独读取。

## 注册

- 方块物品通过物品注册类中的 helper 函数注册；只匹配字面量 `register` 会漏项。
- 声音可以通过 Map 与 ResourceLocation 注册；只读取 RegistryObject 字段会漏项。
- Java 类数与注册数不一定一致，不能把全部类等同于可运行内容。
- 不能按“已知的 `init` 类名后缀”枚举注册类：GeckoLib 盔甲由独立的 `<前缀>ModGeckoLibArmors` 登记（用自己的 `DeferredRegister`，不在 `ModItems`），属性与游戏规则也各有 `ModAttributes`、`ModGameRules`。登记索引应扫描 `init` 下全部含 `register(` 的类，并与全部 `RegistryObject` 声明对账。
- 属性、游戏规则、画、创造栏、物品扩展（燃料、堆肥）等元素没有自己的生成类，内容写在共用的 `init/<前缀>Mod<类型>.java` 中；按生成文件把注册对回元素会漏掉它们，要改用元素定义里的注册名。
- 编辑器元素的触发属性（如 `onRightClicked`、`onTickUpdate`、`onBonemealSuccess`）以过程名指向 `procedures/<名>Procedure.java`；元素间共用的过程（同一模板的门、作物、种植）常以首个元素命名，按名称分组前先去掉元素名。实体定义里的声音字段与 GeckoLib 动画里的声音关键帧也会引用声音，确认“没有播放者”前要一并检查。

## 快照

工程目录中可能留有作者的整体压缩包、`build/libs` 下的构建 JAR 与 `.mcreator/FullBackup*.zip`。来源目录被其他工具操作过时，用它们做来源完整性核对的基线。

## 状态载体

`network/<ModName>Variables.java` 集中声明三类状态：

| 类 | 存储 | 同步 |
| --- | --- | --- |
| PlayerVariables | 玩家 capability | 登录、重生、换维度时同步给本人 |
| WorldVariables | 每个维度的 SavedData | 同步给该维度玩家 |
| MapVariables | 主世界 SavedData | 同步给全部玩家 |

- `PlayerEvent.Clone` 中，持久字段无条件复制，非持久字段只在非死亡复制时复制。迁移时逐字段记录复制策略。
- `DATA_NAME` 是存档名常量，不是状态字段。
- 方块实体数据常写在 `getTileData()`（持久数据）中，同一键可能一处 `putDouble`、另一处 `getInt`/`putInt`；数值标签之间可互读，迁移时按实际取值域定类型。修改后是否调用 `sendBlockUpdated` 决定客户端渲染是否跟随，来源可能只在部分写入处同步。
- 未绑定方块或物品的菜单使用临时 `ItemStackHandler`，关闭时按槽位返还物品；被跳过返还的槽位（如“索引 0 不返还”）中的物品就此转为某个字段的值，这是界面与数据交换的方式，不是丢失。
- 过程里 `ItemStack.EMPTY.getOrCreateTag()` 之类的写入落在空物品上，不改变任何玩家数据；先赋值空物品、后取真实载体的写法会使前面的写入无效。
- `while (计数 < 目标)` 形式的扫描在数据不满足预期时不会结束；迁移时给出扫描上限并记录为来源问题。
- 过程常用字面量键和动态拼接键（前缀 + 序号等）读写 NBT 或字典。动态键要还原生成表达式与索引范围；不同容器的同名键不能按字符串直接合并。

## 系统划分

- 工作区目录、元素名、元素类型与创造栏反映作者的整理方式，不决定玩法归属。同一功能的物品、方块和菜单可能分在不同目录甚至不同 Mod；按赋予该功能玩法意义的规则判定归属。
- 元素之间常只靠字符串注册 ID（`ForgeRegistries` 加 `ResourceLocation`）、命令字符串（`performCommand`，包括自定义的伤害结算命令）和 NBT 键相连。过程调用图看不到这些连接，按调用图聚合功能会漏项。
- 过程可以直接读写任何 Variables 字段及实体、物品、方块 NBT。字段访问与跨过程调用反映生成方式，不是目标系统之间必需的依赖。目标依赖先由各系统职责与数据归属决定，来源访问清单用于核对目标接口是否覆盖全部读写点。

## 入口

- 过程由事件订阅、GUI 按钮消息、实体钩子（初始化、受伤、baseTick 等）、命令、物品与方块回调触发。零静态调用不证明不可达。
- 同一事件可能有多个监听，其中有的只声明局部变量而没有效果；区分真实效果与空监听。
- 语言文件可能存放机器配置（例如长分隔字符串形式的商品列表）。这类内容属于数据，迁到目标数据结构并保留解析语义。
