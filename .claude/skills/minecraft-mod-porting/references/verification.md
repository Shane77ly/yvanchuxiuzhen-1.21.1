# 验证选择与证据登记

适用范围：移植批次的验证选择与证据管理。以下调度规则根据实施中出现的重复运行、夹具失败和证据范围混淆修订；不是任何具体版本 API 的行为证明。资源上限与项目测试政策以项目为准。

## 证据等级

| 等级 | 说明 |
| --- | --- |
| 静态源码核对 | 人工读取的具体来源位置及结论 |
| 自动化验证 | 构建、提取器、测试、资源引用检查等可复现命令及结果 |
| 来源版本实机 | 在来源游戏版本中的实际行为记录 |
| 目标版本实机 | 客户端、专用服务器、多人与存档场景的实际结果 |
| 两版本对照 | 同一场景在两个版本中的结果比较 |

静态注册、事件挂载、正确运行、行为对齐分别记录，不以一个含糊的“完成”覆盖不同证据。没有执行的检查写“未执行”。

## 按风险选择验证

| 改动 | 验证方式 | 不做的形式工作 |
| --- | --- | --- |
| 公式、概率、取整与币值 | 从来源代码独立推导算例；在易回归规则上编写少量确定性测试 | 把实现表达式复制到 expected；`assert true`；给每个参数写相同测试 |
| 附件/组件与死亡复制 | 保存后重读、重登、死亡/非死亡复制的实际结果 | 仅断言对象非空或字段存在 |
| 菜单/网络/库存/账户 | 当前玩家与装置绑定、移动物品、多玩家操作、扣费与产出的实际结果 | 把每个普通方法包成无必要的 mock 测试 |
| 注册、文本和纯资源 | 构建、资源解析、游戏查看；必要时批量引用检查 | 对每个注册 getter 建测试 |
| 实体/技能/特效 | 服务端行为与真实客户端的动作、命中、视觉、声音对照 | 用编译成功代替游戏和视觉验收 |
| 曾复现的 Bug、共享基础逻辑 | 能稳定重现问题的针对性回归 | 为假设中的分支补大量测试 |

每条测试说明它能发现哪种真实错误；能由现有编译或游戏场景充分验证的变更，不另建测试套件。性能记录机器、场景、实体/玩家规模和测量结果，不预填“已优化”。

## 客户端交互与视觉验收

涉及菜单、HUD、按键、客户端输入、同步显示、实体/物品渲染、动画、粒子、声音或动态文案时，验证计划必须覆盖玩家实际操作路径及对应可见结果。静态资源引用或 Smoke 断言只能证明其覆盖范围，不能代替画面检查；客户端检查应同时查看场景结果、保存重进边界和最终界面。需要视觉判断时保存并查看可定位截图，记录截图路径、视口/场景和检查结论；无相关界面或只改纯服务端规则时不为凑证据制造截图。

对使用项目 `runSmokeClient` 的场景，核对选择器、启动日志、场景断言、保存完成日志、`DONE` 与 Gradle 正常退出；逐项报告覆盖的入口、成功/拒绝/扣料/结果/重开等实际行为。`DONE` 或断言数量本身不是通过结论。涉及联网菜单或多人状态时，单机集成世界不能代表多人验收；涉及专服兼容时，客户端通过也不能代替专服验证。每个模块只运行能覆盖其新增或受影响行为的必要场景，相关实现/资源未变时复用已有可追溯报告。

目标版本画面通过不表示与来源版本一致。来源版本实机或两版本对照未执行时，明确记“未执行”；不得将目标版本截图、邻近工程或静态源码核对标作两版本视觉对照。

## 批次验证与复验边界

先说明本批变更可能破坏的路径，再选择最低成本且足够的检查。文档维护不启动游戏；同一批实现集中编译。完整构建、完整冒烟、双端启动和全部历史场景不是每次提交的固定仪式；共享机制、依赖或资源加载确实受影响时才扩大验证。系统最终验收仍覆盖项目批准的全部要求，未执行项不转为已通过。

既有证据绑定代码基线、场景、结果和限制。相关实现、依赖版本、数据或场景未改变时复用结果；新变更只使受影响结论需要复验，不自动作废整个系统的历史证据。没有足够信息判断影响时，明确待核范围并选择对应检查。

启动昂贵场景前先静态核对选择器、初始化、服务端数据写入/同步、环境隔离和预期值来源。这是审阅现有夹具，不要求再建立一套测试夹具的测试。失败后的处理：

| 失败来源 | 下一步 | 证据结论 |
| --- | --- | --- |
| 产品行为与来源不符 | 定位并修复生产实现，再运行能复现的同一场景 | 仅受影响路径为确认缺陷 |
| 检查前置条件、时序或取值错误 | 修正夹具并说明依据；失败前置条件后停止依赖步骤，避免空列表等二次异常 | 未到达的产品路径仍待验证，不宣称产品缺陷或通过 |
| 环境、内存或启动失败 | 记录失败点并处理已识别原因；不能无改动重复启动或自动增加资源上限 | 不产生玩法验收结论 |
| 原因未明 | 保存失败样本，先做静态定位；独立工作可继续 | 保留待核实，不为绿色报告放宽断言 |

每次复跑都应有新修复、新诊断证据或已改变的前置条件。同一失败再次发生而尚无新原因时，停止继续启动该场景，回到定位；不把整个项目挂在反复试跑上。已有必要检查通过后即结束本批验证，除非后续代码改动使结论失效。

`DONE`、进程退出码、日志无 ERROR、断言数量分别只是报告信息；行为通过须看相关断言与覆盖范围。保存失败和成功的证据，当前摘要只保留最新有效结论并链接历史。验证成本只需记录实际运行次数及失败原因，不引入额外绩效报表。
