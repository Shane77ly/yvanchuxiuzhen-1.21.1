# 台账、来源身份与数值迁移

已核对范围：两个 MCreator 生成的 1.18.2 Forge Mod 合并移植的调查与方案阶段；“归属阅读”“无编辑器元素的注册”“来源完整性”三节已用于一次全量内容身份批次（约 3,400 个元素读完归属、3,300 余条注册登记，开发服务端导出与台账一致）。其余方法尚未经过实施批次检验。

## 三份互补台账

| 台账 | 主键与内容 | 防止的问题 |
| --- | --- | --- |
| 内容映射 | 注册表 + 来源 ID → 目标 ID/内部表示、所有者、来源文件 | 漏项、重名、误删、重复注册 |
| 行为对齐 | 稳定功能 ID → 入口/条件/成本/结果/失败/消费者、公式、调用证据 | 将静态注册当作完整功能、只迁移成功分支 |
| 验收证据 | 功能 ID + 版本/场景 → 构建/服务端/客户端/两版本对照结果与证据 | 混淆写了代码、跑过测试和玩家体验通过 |

台账共享 ID，不复制数值正文。完成度同时显示“内容映射覆盖”“行为闭环覆盖”“实际验收覆盖”，不合并成一个含糊百分比。所有来源条目保留处理结果；未裁定项计入未完成。

静态清单是盘点起点，不替代玩家功能清单。每条玩法建立从入口到消费者的完整来源索引。自动生成的候选归属不是已批准的目标映射。

## 来源身份

来源编号、代码符号、注册 ID、显示名和存档键分别记录。编号只是来源命名的一部分：同编号的物品、实体、效果不能凭数字认定属于同一内容；表格行号也不是编号。显示名相同不代表内容相同，公共载体（如同一种书籍物品承载多本内容）要按实例数据区分。

| 对象 | 稳定身份 |
| --- | --- |
| 注册内容 | 注册表类型 + 命名空间 + 路径 |
| 状态字段 | 来源 Mod + 作用域（玩家/维度/世界等）+ 字段名 |
| NBT 或字典键 | 所属物品/实体/方块类型 + 容器路径 + 键 |
| 动态编号键 | 容器 + 生成表达式 + 索引范围 |
| 公式局部变量 | 所属方法与计算角色；不升级为永久数据模型 |

未核实语义保留来源名称并标“待核实”。不因名字像某个属性就改变单位或数据类型。自动命名分组只用于检索；零静态调用者不证明功能不可达，“没有搜到”不能写成“功能不存在”。

## 来源完整性

来源目录被其他工具或代理操作过时，开工前确认它仍是作者的内容。找一个早于这些操作的快照（工程内的整体压缩包、作者构建的 JAR、编辑器自动备份），按路径与内容校验值比较代码、编辑器元素与资源：

- 快照之后由编辑器生成的变化（元素定义与生成代码同步改变，且早于移植工作区建立）是作者的后续开发，作者构建的 JAR 中应能找到其中新增的类。
- 移植工作区建立之后新增的文件（名称含 tmp、test、工具名，拼版图、试作图标、脚本）是草稿，不是来源内容，不迁移；转换清单不得引用它们。
- 同时检查快照之后的修改与删除。比较结果与基线写入来源说明。

## 归属阅读

候选归属（目录、名称、类型、创造栏的批量结果）只决定阅读顺序。按元素读归属时：

1. 先生成每个元素的证据清单：自身触发的过程及其调用闭包；按注册常量与字符串 ID 引用它的其他代码，带引用者的候选单位；引用它的配方、标签、战利品表、进度、函数与语言文件。清单只回答“该读什么”，不判定归属。字符串匹配不区分注册表，同路径的群系与物品会混在一起，阅读时核对。
2. 扫描过程中离开元素自身的操作：玩家与世界状态、命令（含自定义伤害命令）、效果、伤害、传送、给物品、生成实体、打开界面、标签判断。命中者读源码；未命中者确认只改动元素自身或同系列方块。
3. 同模板成员（按材质、颜色、编号复制）读一个代表，再把其余成员的源码替换元素名后与代表比较，只差名称才按同一结论登记。
4. 外部引用逐个看用途。

判定原则：

- 只按 ID 引用（奖励表、商品与价格、配方产物与材料、生成与摆放、目录数据、显示文本）不改变归属。
- 元素唯一的规则在另一系统时，随该系统（例如只用于另一系统附魔效果的方块、唯一用途是种植的种子）。
- 一个过程分属多个功能时按分支拆分：元素身份留在原单位，分支过程归对应系统。
- 公共载体（同一物品按实例数据承载多个系统的内容）留在载体的所有者，各分支经对应系统的入口。
- 读完来源仍没有任何规则可判（无过程、无消费者）时提请负责人裁定，不能把批量候选改写为“已读”。
- 每个元素的依据写明读到的过程或引用者；读元素时一并读过的过程元素按同一结论登记。

## 无编辑器元素的注册

声音事件、属性、游戏规则等注册可能没有对应的编辑器元素，按元素登记的归属表覆盖不到它们。为这类注册另设归属表（注册表、来源 ID、归属、状态、依据），台账同步时读取。声音事件归播放它的系统；多个系统播放时归定义其用途的系统，其他系统按 ID 复用；来源中没有播放者的按名称对应的内容归属，并注明“来源未播放”。归属确定后，声音事件与方块、物品一样由所属单位的内容表登记，声音定义与字幕按单位拆成片段。

## 规则正文记录项

- 规则：功能 ID、来源位置、玩家入口、输入/条件、操作与消耗、结果/消费者、保存和中断、当前决定。
- 数值：单位、计算次序、取整点、随机方式、边界与独立算例；区分定义值、派生值、实例覆盖与兼容字段。
- 架构：状态所有者、可修改者、只读者与同步接收者。

## 定义、实例和执行

- 来源中的长分隔字符串、语言文件内的机器配置等，先按来源解析语义解码，保留顺序、重复项、缺省值和单位，再转换为目标格式。首个匹配查找和累加值依赖原有顺序。
- 定义只描述规则参数；动态行为由明确的代码实现。不为承载来源过程而建立通用脚本引擎。
- 来源物品 NBT 按所有者转换为目标版本的类型化数据。来源拼写可在导入适配中识别，正式模型不沿用含糊拼写。
- 一般合成、熔炼、掉落、标签与世界数据优先使用目标版本已有数据机制；需要状态机的生产流程不塞进无状态配方。
- 同类实体共享确实相同的基础行为；特殊个体保留显式策略，避免巨大的按 ID 分支或为每个编号复制整套 AI。

## 数值迁移

每条公式记录：输入与单位、有效范围、运算顺序、整数/浮点规则、截断位置、随机分布与抽样次数、边界条件、调用入口、消费者，以及至少一组手算或来源版本运行算例。领域模型可以更清晰，但计算语义必须等价。

不把来源 double 无条件换为整数。离散整数值在明确取整规则后可采用有溢出检查的整数单位；倍率和连续属性按来源精度核对。界面显示的小数位不代表服务端精度。

同一计算的预览与执行若在来源中确实不同，先保留两种语义的证据再裁定；推荐共享输入解析与公式实现，用明确的预览/执行语义决定输出，避免复制代码。

## 许可证

发布前收集每类第三方资产、库与来源工程的许可证、署名和来源。元数据中的许可证声明不能替代逐资产核对，也不能从新项目许可证推导所有资产可重新授权。
