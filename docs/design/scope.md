# 范围与保真原则

## 已确认

负责人要求从全新独立项目完整移植两个 1.18.2 Mod，目标为 Minecraft 1.21.1 + NeoForge + Java 21，合为一个可安装 Mod，内部按系统组织。建立编号和变量 Excel；先完成调查与架构评审，再由负责人明确启动 goal。当前没有启动 goal 的授权。

本轮交付调查证据、架构草案、全量实施范围及文档规范。所有目标类、数据模型与依赖选择仍为提案，没有移植游戏代码。统一使用“1.18.2 版本”“1.21.1 版本”；技术路径中的原始名称照实保留。

## 完整范围

两个工程的注册内容、有效行为、命令与管理设施、菜单/HUD/按键、世界投放、模型/纹理/动画/声音，以及状态保存和多人交互均在范围内。银行、拍卖、蛊虫、容器、生活生产、副本等不因已有 1.21.1 工程曾暂缓而排除。

每项来源内容的去向、玩家路径检查和行为保真规则，以[移植技能](../../.claude/skills/minecraft-mod-porting/SKILL.md)的“核心规则”与“系统工作单”为正文。本项目计数口径：实体类型数包含弹体和形态，不当作生物种数；方块物品计入物品数。

## 行为与技术变化

处理原则见移植技能“核心规则”。本项目补充：已有 1.21.1 工程的新增设计仅作独立参考，不进入此次来源基线。

功法实例成长、银行玩家归属和现场拍卖等已发现事实已进入 [架构提案](../development/architecture.md)。这些事实约束技术设计，不能为了模型统一改变内容含义。

## 评审前后仍需明确的事项

| 事项 | 当前建议 | 对范围的影响 |
| --- | --- | --- |
| 两个来源命名空间和编号 | 保留资源 ID，Java 名称语义化，Excel 映射 | 减少资源引用变动；不等于存档升级兼容 |
| 1.18.2 世界/玩家存档迁入 | 内容移植与存档转换分别估算；尚未承诺直接升级 | 需要确认是否包括离线转换器和世界数据验证 |
| 1.21.1 现有工程存档迁入 | 不自动兼容既有重做格式 | 若需要，另建立真实格式对应表 |
| 界面表现 | 保留全部操作、信息和反馈，布局可另评审 | 当前未设计屏幕；不自动采用既有重做 UI |
| 明确存在的源码问题 | 按 [调查问题表](../reference/legacy/source-survey.md)逐项裁定 | 影响炼丹门槛、阵法效果和交易找零等具体行为 |

其余调查缺口作为每个系统的核对任务记录；需要决定的矛盾应在该系统实现前解决。完整范围不会缩减为仅一门功法、一个生物或一条生产线。
