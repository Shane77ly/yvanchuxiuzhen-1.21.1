# 炼丹、药理、药物与毒药：架构调查与提案

来源事实与目标方案分别陈述。目标方案未批准；源码定位采用 [系统导航](../README.md)的 A/B 规则。
## 1.18.2 实际结构

炼丹入口、药理台、百草鉴、分丹、合丹、丹方和服用是不同流程。`B:LiandanBeginProcedure:445–488` 将药效列表写入临时产物，设定数量、加工时间、职业经验和炸炉参数；药效以 `danyaoxiaoguo{i}/danyaolevel{i}/danyaotick{i}` 编号。

**等级检查已追到图源**：`elements/LiandanBegin.mod.json` 的 `LiandanLVjiance` 调用位于顶层游离块，不在 `event_trigger` 子树；生成 Java 未调用它，与连接图一致。`fanhuizhi` 初始化为 0。恢复游离块功能属于待裁定行为变化，不是机械移植。

药草目录由 Worldbegin 写入 `caoyaolist`，每条为药材和若干药效/运算符/数值组。玩家 `playercaoyaojiexi` 保存辨识。炼丹产物之外还要迁移容器装填、服用、即时/持续药效与毒药结束回调。

## 目标所有权与接口提案

定义层分药材药性、丹方和药效动作；实例层分丹药组成与数量；炉次保存输入快照、操作人、职业快照、进度、失败条件和待交付产物。药理台编辑内容属于实例或定义覆盖，需保留其真实操作范围。

入口：辨识、预览、开始炉次、推进/结束、分丹、合丹、服用。药效根据实际来源调用成长、属性、战斗或状态入口，不能把效果 ID 全部交给一个任意 NBT 修改器。

加载装置 → 恢复库存/炉次 → 正常加载期间推进 → 生成产物并标脏；菜单仅同步打开者所需内容。多人切换职业快照与卸载中断的语义是明确评审点。

## 数值与完整性

保留药效相加/相减等运算顺序、等级/持续时间单位、随机数量、分合丹损耗及失败结果。动态药效列表以原有 `shuliang` 控制，不随意截断为固定四种效果。发布前验证所有丹药和毒药消费者，当前未进行游戏验收。
