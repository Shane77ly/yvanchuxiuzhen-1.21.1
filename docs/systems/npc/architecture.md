# NPC 身份、交互与世界定义：架构调查与提案

来源事实与目标方案分别陈述。目标方案未批准；源码定位采用 [系统导航](../README.md)的 A/B 规则。
## 1.18.2 来源

修士/商人具有不同交互与 tick 过程，并由标签参与免伤/关系判定。`B:NpcshujvjiaruProcedure:27–85` 从 `npc.data.list{n}` 语言键逐项解析 `/` 分隔的类型化三元组，写入维度 `worlddata` 的嵌套标签；该字段由 Worldbegin 初始化为隐藏钻石物品。

因此 NPC 定义不是每个实体单独硬编码，也不是自然应放入全局玩家档案。语言解析通过键长度等条件判断结束，导出时必须记录原始顺序与停止条件。

## 目标所有权与接口提案

NPC 定义保存身份、展示、行为配置和对话入口；实体保存当前实例身份/状态/关系。定义从结构化数据加载，显示语言单独引用。world 负责投放与城镇，quest 负责对话/任务推进，economy 负责交易与现场竞价。

交互入口将玩家、NPC 实例和入口 ID 交给对应系统；不要把任务、银行和拍卖状态塞回 NPC 基类。管理编辑器修改的实例覆盖与资源定义明确区分。

## 需保留和核实

完整范围包含不同商人、特殊 NPC、对话、管理设置和现场拍卖参与。来源自然生成、结构生成、固定位置及动态生成分别登记；NPC 数据表存在不等于某角色已在生存世界投放。专用服务器不加载模型/屏幕类，客户端仅消费可见身份与动作。
