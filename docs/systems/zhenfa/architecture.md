# 阵位、阵元、阵旗与阵法效果：架构调查与提案

来源事实与目标方案分别陈述。目标方案未批准；源码定位采用 [系统导航](../README.md)的 A/B 规则。
## 1.18.2 结构与入口

`B:ZhenfajianceProcedure:32–201` 清空派生结果后按预置坐标扫描 88 个位置；源码虽然声明长度 232 的坐标数组，当前主循环并非遍历全部 232 个。内层 8/16/40/64/88 的分段分别写阵位、距离、触发/目标/控制及元素修正。

`ZhenjiGengXinYouXiKeProcedure:23–69` 要求阵法有效、`powerneed > 0` 且余额严格大于费用，再按感应、红石或主动触发调用效果。感应按扫描到的实体循环，调用和扣费也位于相应分支，不能自动改成每轮只扣一次。

`ZhenfaxiaoguoProcedure:14–29` 分派金、水、木、火、土、阳、阴、空间共八条效果入口。母旗/子旗、目标队伍和位置也参与执行。

## 费用与分派矛盾

主检测在 `ZhenfajianceProcedure:198–199` 依次调用 4、5 两个过程。`Zhenfajiance4Procedure:162–163` 写等级 `floor(levelzong / shuliang)` 与基础费用 `ceil(levelzong / 4)`；`Zhenfajiance5Procedure:18、25、161` 用初值为 0 的倍率乘基础费用，再 `round` 写回。

阴2及复制分支写 `SoulAttackDamage`，阳4及相关弹体写 `ManaAttackDamage`。显式读取这些实体键的计算过程没有从当前结构入口图到达；弹体复制字段并非实际扣血。详见 [战斗消费者核对](../combat/architecture.md)。不能以注册数量或有粒子判定伤害已生效。

## 目标所有权与接口提案

阵基拥有阵元布局的解析结果、能量、触发方式和当前状态；阵旗保存绑定的维度与位置。布局定义、放置实例、阵元材料和执行状态分开。配置读取保存来源顺序和空位意义。

入口为布局检测、供能、设置触发、绑定旗帜、触发和结束。效果委托 combat/skill/xiulian/world 的具体操作。玩家 UI 只提交操作，不提交完整阵法结果。阵基/阵元随区块保存，检测缓存不能成为第二份布局真值。

## 裁定与验收

需要裁定：费用倍率缺失、五行执行分支错配、火2类别错配、伤害消费断链，以及严格大于余额/逐目标扣费是否保留。不能擅自填入推测倍率或创造五行效果。建议先以已有配方、效果资源和实际玩法说明确定每一项预期结果，再批准具体行为调整。跨维度、拆阵、移旗、重载与多人触发都属于完整范围。
