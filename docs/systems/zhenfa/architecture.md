# 阵位、阵元、阵旗与阵法效果：架构调查与提案

来源事实与当前实现范围分别陈述。阵元、阵基、阵旗及阴/空间/阳与五行来源分支已按完整移植授权实现；未批准的来源行为调整仍单列保留，源码定位采用[系统导航](../README.md)的A/B规则。
## 1.18.2 结构与入口

`B:ZhenfajianceProcedure:32–201` 清空派生结果后按预置坐标扫描 88 个位置；源码虽然声明长度 232 的坐标数组，当前主循环并非遍历全部 232 个。内层 8/16/40/64/88 的分段分别写阵位、距离、触发/目标/控制及元素修正。

`ZhenjiGengXinYouXiKeProcedure:23–69` 要求阵法有效、`powerneed > 0` 且余额严格大于费用，再按感应、红石或主动触发调用效果。感应按扫描到的实体循环，调用和扣费也位于相应分支，不能自动改成每轮只扣一次。

`ZhenfaxiaoguoProcedure:14–29` 分派金、水、木、火、土、阳、阴、空间共八条效果入口。母旗/子旗、目标队伍和位置也参与执行。

## 来源差异与当前边界

阵基、阵元、母旗/子旗与罗盘的注册、方块实体、布局、供能、绑定控制、阴1–4、空间1–5、阳1–4及五行来源复制执行分支已接入；阳系模型表及内容/资产定向转换已接；后期消费者、多人和跨维度仍待。阵旗来源会把 qimubiao* 坐标写入目标位置下方的任意方块实体，目标当前只接受阵基方块实体，保留数据所有者约束，记入统一问题索引待裁定。`formation` Smoke 于2026-11-14完成，依次覆盖阵基和阵元；报告含54条INFO、0 FAIL、DONE，保存重进与正常退出完成，证据归档于`build/diagnostics/r15-zhenfa-formation-20261114/`。该历史结果只证明当时必要单项；后续空间8项、阳/五行19项受控检查另见本月志，来源版本实机、多人、跨维度、阳四19×19破坏与完整表现仍未验。

## 目标所有权与接口提案

阵基拥有阵元布局的解析结果、能量、触发方式和当前状态；阵旗保存绑定的维度与位置。布局定义、放置实例、阵元材料和执行状态分开。配置读取保存来源顺序和空位意义。

入口为布局检测、供能、设置触发、绑定旗帜、触发和结束。效果委托 combat/skill/xiulian/world 的具体操作。玩家 UI 只提交操作，不提交完整阵法结果。阵基/阵元随区块保存，检测缓存不能成为第二份布局真值。

## 裁定与验收

需要裁定：费用倍率缺失、五行执行分支错配、火2类别错配、伤害消费断链，以及严格大于余额/逐目标扣费是否保留。不能擅自填入推测倍率或创造五行效果。建议先以已有配方、效果资源和实际玩法说明确定每一项预期结果，再批准具体行为调整。跨维度、拆阵、移旗、重载与多人触发都属于完整范围。

## 阵基效果：阴系与空间系（2026-11-15）

`FormationBaseBlockEntity`在来源触发时分派`FormationEffects`。阴1–4保留实体神识增长、伤害标记、移除实体和`NoAI`写入；空间1在目标坐标附近按等级施加缓慢，空间2写入`jinkong`，空间3执行检测反馈，空间4传送阵基范围内的实体到目标坐标，空间5沿来源阵位组合和境界选择维度，再使用显示名构造传送命令。实体筛选继续按距离排序，并保留来源队伍允许状态在本轮扫描中的锁存。

空间2通过combat公开的`StatusEffects.markEntityFlightBlocked`写入标记；`SkillFlight`与`FlyingInstrumentEntity`各自在来源推进位置调用`consumeEntityFlightBlock`后执行禁空反应。空间3的`zizhijiancefankui`命令由flow注册，具体反馈由`FormationInspection`负责。反馈按0.5格范围和距离顺序发给参数坐标附近玩家，命令坐标保留小数。已对照`typed_field_accesses.csv`的本过程外部读取：修炼值经`Cultivation`、基础属性经`PlayerAttributes.baseValue`、功法栏与实例经`Techniques`查询，来源等级2误读`jinengName`仅在该栏实际带法术技能组件时由`Skills`查询，不以功法名替代。

反馈可达输出按来源顺序为：等级1以上显示实体名；等级2以上显示境界及经验，否则只显示境界；玩家随后按等级4/5/5/6分别显示基础血量上限、物理攻击、法术攻击、精神攻击，等级4显示非零罡煞，等级6显示非零功德但仍使用“罡气／煞气”文案，等级3以上显示功法名/品阶和整数层数，等级2显示功法栏的`jinengName`，等级7显示吸纳效率，等级8显示晋升难度。非玩家在等级4/5/5/6分别读取生命属性基础值、攻击属性基础值、`mana_Att`和`soul_Att`。来源对非玩家强转`LivingEntity`并直接读取属性，没有额外过滤，目标保持。

`A:ZizhijiancefankuiGOProcedure:73–150`的灵根分支嵌在`zhenlevel >= 2`的`else`中，却再次要求等级2或3，因此只有灵根输出不可达；`:151–243`的属性、功法、吸纳效率和晋升难度位于该`else`之外，均可达。此前将全部高阶输出判为不可达的结论已更正，并补齐缺失实现。灵根不可达、等级2错读键与功德文案错配按来源保留，交统一问题索引集中复核。

空间5无匹配阵位或境界时来源维度字符串保持空值，仍构造原始命令；目标不添加默认维度或改用UUID替换显示名。可用维度、实体显示名解析、跨维度目标路径、空间1–5自然触发和多人行为均未验，待统一问题索引集中登记。灵根反馈的不可达输出保持来源，待集中复核。

## 阵元方块（2026-11-14）

zhenyvan持有两槽材料/伪装库存、方向能力、含水状态、比较器、破坏回收、布局坐标和展示角。主手含buzhencailiao标签时按来源把一件材料放入槽0，空手或后续材料交互取出；其他方块物品切换槽1伪装。阵元不直接打开其保留的三行菜单，其他系统可通过公开查询/写入操作读取材料和阵基坐标并更新展示字段。

来源`ZhenyvanBlockEntity.getCapability`在非空方向返回`SidedInvWrapper`，空方向调用父类。Forge40.1.0的`BaseContainerBlockEntity`补丁以`createUnSidedHandler()`创建`InvWrapper(this)`，`getCapability`未限制方向，因此来源具有六面和无方向共用的两槽库存。布局过程`Zhenfajiance4Procedure:73–90`直接通过空方向能力读材料，没有普通库存回退；删除该能力会阻断阵基检测。目标显式注册六面包装及空方向`InvWrapper`以保持来源；精确父类机制沿用[技能已核实依据](../../../.claude/skills/minecraft-mod-porting/references/targets/neoforge-1.21.1.md)。[Q148](../../reference/legacy/source-survey.md#具体问题与裁定位置)记录此前只读子类而误判为扩展能力、现已更正，必要单项已确认。材料/伪装同步、无方向插入/六面共库、序列化、真实保存重进及破坏回收必要单项通过；检测坐标和角度由所属系统公开操作受控写入，不代表自然检测路径。阵元不代表阵基检测或效果路径完成。
