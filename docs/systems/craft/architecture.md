# 工艺：架构调查与提案

来源事实与目标实现分别陈述。石磨与石碾按已批准的系统归属和本批来源规则实施，其他工艺设备仍为调查与提案；源码定位采用[系统导航](../README.md)的 A/B 规则。

## 1.18.2 范围

砧板/石磨、木匠台、纺织/缝纫、陶轮/陶坯与蚕丝链。陶轮界面的 `TaoguanGuipageup`、`TaoguanGuipagedown` 由 `TaolunGuiButtonMessage` 触发，翻的是陶轮配方页。蚕蛾只由 `A:CanheGengXinYouXiKeProcedure:594` 生成，实体类没有专属过程；结茧、羽化由蚕盒驱动。

## 石磨与 Grind 来源核对（2026-11-09）

`A:block/StonemillBlock:136–147` 的右键入口调用 `A:StonemillZaiFangKuaiShangYouJianProcedure`。该过程在 `:36–51` 潜行时打开石磨菜单，在 `:53–61` 非潜行时从石磨坐标以权限4、屏蔽输出执行 `grind 4`，随后把动画设为1。两个来源 Mod 的 1.18.2 版本 Java 中，两种设备通过该过程形成 `grind` 的自然调用入口。

`B:command/GrindCommand:24–64` 注册的 `/grind` 自身没有权限门槛；它使用命令来源坐标，把首个参数作为加工次数，也不要求当前位置是石磨。`B:GrindGoProcedure` 只操作该位置库存与工艺原料产物，没有药性或炼丹状态。两个元素按实际职责从 liandan 移归 craft；以下是来源事实；对应目标实现与当前分级证据见下节。

| 槽0主料 | 槽2辅料 | 单次产物 |
| --- | --- | --- |
| `shicai_001` ×4 | 无 | `shicai_00102` ×1 |
| `shicai_002` ×4 | 无 | `shicai_00202` ×1 |
| `minecraft:wheat` ×4 | 无 | `shicai_003` ×1 |
| `fuluzhushablock` ×1 | 无 | `fuluzhushaitem` ×1 |

配方表来自 `B:GrindGoProcedure:107–110`。执行顺序与来源异常如下，后续实现须保留已核实行为，不自行改写产量：

- `:35–76` 先按槽1原数量N循环N次，每次掉落一份完整N数量的旧栈副本，落点为命令坐标加 `(0.5,0.9,0.5)`、拾取延迟10刻，之后清空槽1。没有参数、非法参数或不匹配配方时也先执行这一步，旧输出可能产生N²件。
- `:78–104,114–153` 缓存槽0初始物品和数量；次数按double解析，失败为0，循环时转int。有辅料配方每轮重读槽2，无辅料配方不读取槽2，槽0数量条件沿用初始缓存，因此一份足够单次加工的主料可能在多轮中重复满足条件。
- `:154–227` 以默认产物新栈覆盖槽1，数量为已有槽1数量加本次产量，不保留旧组件，过程内没有显式输出上限检查；随后扣槽0，再扣槽2。最终写库存仍经过容器实现的堆叠上限，不能据此解释为无限堆叠。

2026-11-09 归属调整后为128个元素、48个已读；2026-11-10 补读石磨菜单和两份自然配方后，登记接入时为51个已读、77个候选。来源阅读覆盖与目标玩法验收分别登记。

### 库存、移动与保存

槽0主料在(43,44)，槽1成品在(115,44)，槽2辅料在(61,44)。手动只禁止向成品槽放入，主料和辅料均不增加标签过滤。六方向暴露全部三槽，自动插入限槽0/2、抽取限槽1；研磨使用无方向可写包装，不受自动插入限制。

设备槽 Shift 移到玩家库存时逆序扫描，玩家槽先顺序尝试设备0–2，失败才在主背包与快捷栏互移。向已有栈合并时也检查该槽 `mayPlace`，保持来源覆写的成品过滤，不为碗增加专属优先级。`stillValid` 按来源恒真；关闭菜单保留真实库存，没有新增未绑定菜单玩法。

库存使用 `ContainerHelper` 与来源战利品表分支保存，更新包含完整方块实体标签。设备没有加工进度或服务端加工 ticker。方块提供者的默认 `createMenu` 仍返回来源独立三行箱子；自然潜行入口使用 `StoneMillMenu` 绑定设备三槽，不能混同两条路径。

1.21.1 版本 NeoForge 21.1.265 精确源码中，`InvWrapper.setStackInSlot` 委托容器写入，`BaseContainerBlockEntity.setItem` 按物品/容器上限截栈并标脏。目标设备沿用该层，而非自行实现无限成品堆叠。来源研磨过程的N²旧输出与主料初始数量缓存仍按前节保留。无辅料分支按来源延迟读取槽2，以保留 `/grind` 对只有主料/成品两槽的通用库存行为；该通用两槽路径尚未运行验证。

### 动画与资源

两个设备的来源资源分别为 `geo/<设备>.geo.json`、`animations/<设备>.animation.json` 与 `textures/block/<设备>.png`，菜单为 `textures/screens/stonemill_gui.png`。物品模型保留 `builtin/entity` 父标记与来源持物变换，避免丢失 Gecko 物品渲染入口。两份几何、两份动画、两张方块纹理与菜单纹理共7文件已逐字节核对来源一致；模型转换保留上述父链与变换。资源清单共13280项、既有缺失19项，未包含本批craft资源缺失。两份有序合成和设备挖掘标签已生成，自然合成操作尚未执行。

来源 `animation` 状态允许0–2；自然右键只写1，两份动画文件只定义循环待机0与4秒一次性动作1。目标保持客户端控制器在动作停止后复位状态，不为此添加80刻服务端加工任务或虚构动作2。客户端的本地动画复位、服务端方块状态保存与再次请求必须在运行时分别核验，当前未作实测结论。

### 归属与外部边界

两种设备、菜单、研磨命令和库存过程归 craft。食材、调味、辰砂矿与朱砂按注册 ID 参与七配方，不改变其 cooking/fulu 归属，也不直接调用其内部实现。辰砂矿自然生成归 world，接通石磨不代表矿物自然获取已完成。

本批 `typed_field_accesses.csv` 按设备/研磨类名检索0行；完整来源方法未读写玩家能力字段，因此没有新增跨系统玩家持久化写入口。其他设备仍按其自身来源链继续调查。
