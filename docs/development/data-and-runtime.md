# 数据与运行时提案

本稿按 1.18.2 实际状态载体设计；各项均待批准和实现。[目标 API 证据](../reference/target-api.md)只确认机制，不代表已经完成运行验证。

## 状态归属与完整数据流

| 数据 | 存储与加载 | 修改入口 | 消费与同步 | 保存 |
| --- | --- | --- | --- | --- |
| 功法、材料、药效、图纸、商品、任务等定义 | 系统自己的数据文件；由目标数据加载机制解码 | 数据文件或已有管理工具支持的实例覆盖 | 所属行为查询；客户端仅获得实际显示所需部分 | 静态定义不写入每个玩家存档 |
| 境界、修为、待吸收池、寿元、体质、金丹/元婴 | 玩家 Attachment | 成长服务 | 功法/药物/任务通过方法提交变更；本人收到显示更新 | 随玩家保存 |
| 功法绑定、等级、经验、实例属性 | 功法书 ItemStack Data Component | 绑定、研习、参悟、继承方法 | 功法栏持有书籍，属性服务读取组件；菜单显示同一实例 | 随物品及所在库存保存 |
| 技能栏、饰品栏、本命槽 | 所属系统的玩家 Attachment 库存 | 服务端装备/取出操作 | 属性、能力、菜单读取实际栏位 | 随玩家保存，死亡规则按栏位核对 |
| 职业经验及符头/符胆知识 | 对应系统玩家数据 | 该职业的生产/学习结果 | 门槛查询和个人面板 | 不复制一份独立的全职业显示档案 |
| 银行账户与个人任务 | economy / quests 的玩家 Attachment | 存取、兑换、交易、任务推进方法 | 银行/任务界面与所属玩法 | 保留玩家数据归属；未设计离线账户操作 |
| 玩家材料计数仓 | storage 的玩家 Attachment，按材料 ID/等级/品阶记录数量 | 存入、取出、自动收集与扣料入口 | 分页菜单生成显示物品；生产查询同一份数量 | 随玩家保存；不随材料袋物品转移 |
| 装备、丹药、符箓、图纸、容器内容 | ItemStack Data Component | 产物所属系统操作；修改时替换组件值 | 装备、服用、释放、合成、交易与库存 | 随物品保存，组件实现按目标源码确认 |
| 炉次、库存、阵法、现场拍卖 | 各 BlockEntity | 当前合法交互、装置 tick 或红石等来源入口 | 打开菜单者同步进度/槽位，其他玩家只接收可见表现 | 修改后标脏；区块保存与重载恢复 |
| 生物等级、主人、形态、采集与培养 | 实体 NBT/Attachment，按数据生命周期选择 | 实体生成、AI、伤害/交互及采集 | 必要字段交给实体同步数据或附件同步，跟踪者消费 | 随实体保存 |
| 维度场景状态与全局悬赏等 | 按实际范围选维度 SavedData 或主世界 SavedData | world / quests 的所属服务 | 场景生成、查询及相关菜单 | 标脏后随所属世界保存 |
| 属性派生结果、GUI 暂存、施法目标缓存 | 实体属性、缓存或当前会话 | 属性计算/界面交互/能力过程 | UI 与运行逻辑读取 | 按语义决定；不把每个显示值写为永久字段 |

211 个状态字段只涵盖两个工程的三种 Variables 类。大量状态还在物品、实体、方块 NBT 中；[动态数据族](entry-and-dependency.md)已记录主要载体和范围，[动态表达式目录](../reference/legacy/inventory/dynamic_key_catalog.csv)保留 630 个表达式分组。不能把字段数或表达式数当作全部存档槽位数。

`renwuitem` 是 B 登录时创建的隐藏铁锭，用来装任务、材料计数仓及交易等数据；`worlddata` 是隐藏钻石载体。这些技术载体在目标分别拆成所属系统数据，不能因为来源类型为 ItemStack 就让全部内容成为可转移物品。B 的功法同名声明与 A 的实际栏位也分别核对，详见功法正文。

`WorldVariables` 的实际存储是维度数据，`MapVariables` 从主世界数据存储取得。迁移依照调用处的作用范围，不能按英文类名猜测全局性。

## 加载、修改、同步、保存

注册先完成类型、菜单、组件、附件与消息；静态 Item/Block 类型不在资源重载时增加。系统定义由版本对应的数据加载 API 读取，资源引用错误报告文件、字段和 ID，不用空对象伪装成功。

玩家/物品/实体/方块各从自己的存储恢复状态，派生属性由原始状态重算。修改只有所属行为入口负责；网络发送只负责传达变化，不代替保存。持久化 schema 记录实际格式；出现真实格式变更再编写迁移，不预制尚不存在的多个历史版本兼容分支。

功法书的实例成长必须随书保留，不能同时在玩家档案中存第二份独立的等级/经验。菜单暂存若可删除，应先核对取出、关闭、移动、死亡时是否承担物品归还；不能仅凭 `linshi` 字段名认定它无用。

## 服务端操作

客户端发送操作意图，例如“在当前炼器菜单开始这一炉”。服务端从当前菜单绑定的真实装置、槽位和玩家身份取输入，验证该操作确实允许后计算并执行。客户端提交的余额、职业等级、伤害或最终产物不能作为结果依据。

这种校验有具体来源：1.18.2 的 `TripodGUIButtonMessage` 接收坐标后检查区块存在，再直接调用开炉过程；交互时又把职业值写入共享方块。新入口应绑定菜单和操作玩家，避免不同玩家的职业快照互相覆盖。是否锁定一次加工的职业、是否允许协作换人，是需对照的玩法语义，不以技术框架代替裁定。

同一服务端主线程顺序完成输入检查、扣费、状态推进和结果写入。普通按钮操作采用当前菜单/炉次/领奖状态判断，不一律附加请求 UUID、revision、重试队列或分布式事务。

银行和现场拍卖按实际账户、库存与拍卖阶段完成扣款和交付。若某条真实业务涉及多份存档之间的资产交接，应单独设计中断恢复并验证；本提案不声称同一 tick 写入等于磁盘原子性，也不提前建设全项目事务平台。

## 同步选择

本地 NeoForge 21.1.228 的 `AttachmentType.Builder` 已提供 `sync`、接收者过滤及自定义同步处理器。小型适配数据可以直接使用；只有需要不同显示内容或菜单结果时再定义 payload。不能沿用“1.21.1 附件必定完全手写同步”的记忆。

| 内容 | 接收者与时机 | 选择 |
| --- | --- | --- |
| 个人成长/职业/知识面板 | 本人登录、重生及相关数据改变 | 附件同步或本系统显示快照，按实际范围二选一 |
| 槽位与制作进度 | 当前菜单查看者 | 目标菜单机制；超出其数据表示能力的内容使用专用 payload |
| 妖兽形态、动作、必要等级 | 正在跟踪实体的客户端 | 实体同步数据或附件同步 |
| 技能声画表现 | 实际可见范围内玩家 | 所需位置、动作和参数；服务端负责实际效果 |
| 静态说明 | 确实显示该内容的客户端 | 优先资源包，数据依赖服务端时同步必要摘要 |

数据变更合并发送；不在每 tick 同步完整档案。菜单关闭、退出服务器及实体移除时结束对应临时状态。需要严格区分“公共展示信息”和“私人银行/任务信息”。

## 生命周期

普通死亡、非死亡实体复制、寿元耗尽及轮回分别列出数据去向。1.18.2 普通 Clone 与轮回符走不同逻辑，不能统一清空或统一全复制。附件 `copyOnDeath` 根据逐项策略设置；玩法惩罚只在其负责入口执行。

[183 个字段复制表](../reference/legacy/inventory/clone_policy.csv)已核对：A 的 157 个字段在所有 Clone 分支复制，9 个仅非死亡复制（六个 colddown、gongjian、gongjianjineng、chuansongitem）；B 为 15 个所有 Clone 复制、2 个仅非死亡复制（bankceshi1/2）。这是来源 Variables 的复制行为，不证明普通实体 NBT 也执行相同规则。轮回符主动重置另见成长正文。

[211 字段生命周期表](../reference/legacy/inventory/state_lifecycle.csv)按 Mod/作用域/字段匹配 5,752 处可识别访问，另 315 处未解析成员未纳入归属统计。13 个声明未找到显式外部消费，保留记录并继续查证；零访问不能作为删除依据。

装置仅在正常加载时推进，离线/卸载是否补算以来源行为为准。施法过程保留 UUID、维度键和坐标等身份信息；临时实体引用只在其有效世界生命周期内使用。不要默认增加区块强加载和离线收益。

先保留来源的 tick 周期、随机抽取顺序、取整位置和失败结果，再依据测量改进热点。修改方块触发阵法重检、属性来源变化触发重算等优化必须证明不改变实际规则。性能预算在真实场景测量后填写。

## 配置与重载

优先使用目标版本已有配方、标签、掉落及数据加载机制。需要自定义目录时按系统建立类型化定义，数据只解析一次，不在每次点击或每 tick 重拆超长字符串。

全量运行中热重载不是完整内容移植的当然要求。先逐项确认管理工具和数据包重载的现有操作需求；某种定义只在重启后生效就明确说明。若保留运行时修改，必须规定进行中的炉次、技能和拍卖使用哪一份数据，并采用目标加载流程报告失败。当前不设计跨所有系统的多代快照、回退和暂停平台。

验证选择见移植技能的[验证参考](../../.claude/skills/minecraft-mod-porting/references/verification.md)。本轮未进行游戏构建、服务端启动或存档运行验证。
