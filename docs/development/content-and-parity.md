# 内容与对齐流程

台账结构、来源身份、规则记录项、定义与数值迁移、资源与表现核对、多 Mod 合并的通用做法，以移植技能的参考为正文：[台账与数值](../../.claude/skills/minecraft-mod-porting/references/parity-ledgers.md)、[资源与表现](../../.claude/skills/minecraft-mod-porting/references/assets-and-presentation.md)、[多 Mod 合并](../../.claude/skills/minecraft-mod-porting/references/multi-mod-merge.md)。本页只记录本项目的来源、决定与适用范围。

## 来源优先级

两个原始工程的源码、MCreator 元素和资源是事实证据。现有 1.21.1 工程中的1.18.2 版本研究文档可用于定位，但其中的采用决定、跳过范围和移植状态不传递到新项目。

新项目的[静态清单](../reference/legacy/inventory/README.md)保存注册声明、玩家字段、来源路径和文件哈希，作为盘点起点。

## ID 与资源建议

一个 Mod ID、一份发布包，同时保留两个 1.18.2 命名空间 `yvanchuxiuzhen` 与 `yvanchuxitong` 中已有内容 ID。新 Java 包名统一规范化；代码模块边界不受1.18.2 命名空间限制。平台支持按命名空间创建注册器的源码依据见[API 核对](../reference/target-api.md)。

新 Mod 元数据不再声明两个 1.18.2 Mod 的相互依赖。映射键、显式改名登记和 modid 判断的改写按多 Mod 合并参考执行。最终单 Mod 携带1.18.2 命名空间的注册、资源加载、翻译、结构解析与打包行为须在基础阶段实测，当前是建议方案。

## 台账现状

三份台账按台账参考建立。当前工具生成来源身份、文件证据与全量候选模块归属，后者依据编辑器目录和明确例外，不是已批准目标映射。1.21.1 ID 和逐项行为验收仍未填写；来源结构可达与实际验收分别记录。

## 本项目的定义与数值适用

- 常量、配方、商品池、词条、功法属性和技能参数按系统定义结构化表达；首期不造通用脚本语言或解释全部 Procedure 的引擎。
- 1.18.2 装备、法宝、丹药、书籍 NBT 按所有者转换为类型化组件。
- 专用鼎炉、阵法和银行保留业务服务；不同 Boss、特殊妖兽和技能保留显式策略。
- 余额等离散整数在明确取整规则后可采用有溢出检查的整数单位；五行、倍率和连续属性按1.18.2 精度核对。
- 炼器预览与实作若1.18.2 版本确实不同，按台账参考的预览/执行规则先保留两种证据再裁定；架构阶段不宣告数值已统一。

## 界面与表现

本轮不设计具体 UI 布局；之后优先保持1.18.2 操作能力和视觉识别，逐项确定允许改进。中文文案只表达玩法信息。

## 来源与可移交性

当前引用1.18.2 工程的本机只读路径，已生成清单有 SHA-256 以识别来源变化；没有复制整套1.18.2 工程进新目录。协作者需要提供相同来源，并使用提取工具的 `--source-workspace` 参数定位。

许可证、署名与来源资料归 `docs/licenses`；收集要求见台账参考的“许可证”。
