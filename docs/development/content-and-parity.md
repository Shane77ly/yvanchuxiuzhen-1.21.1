# 内容与对齐流程

## 来源优先级

两个原始工程的源码、MCreator 元素和资源是事实证据。现有 1.21.1 工程中的旧版研究文档可用于定位，但其中的采用决定、跳过范围和移植状态不传递到新项目。旧源码本身的未闭环行为明确登记；真实游戏验证与静态推导分开。

新项目的[静态清单](../reference/legacy/inventory/README.md)保存注册声明、玩家字段、来源路径和文件哈希。它是盘点起点，不替代玩家功能清单。未来每条玩法必须建立从入口到消费者的完整来源索引。

## ID 与资源建议

一个 Mod ID、一份发布包，同时保留两个旧命名空间 `yvanchuxiuzhen` 与 `yvanchuxitong` 中已有内容 ID。新 Java 包名统一规范化；代码模块边界不受旧命名空间限制。平台支持按命名空间创建注册器的源码依据见[API 核对](../reference/target-api.md)。

选择保留命名空间，是为了减少模型、配方、标签、结构 NBT、命令字符串、物品表和世界引用的无意变化；并非承诺两个旧 Mod 的二进制 API 或旧世界可直接运行。新 Mod 元数据不再声明原先相互依赖。凡通过“是否加载旧 modid”决定行为的代码需逐处改为新项目内部能力判断。

保留 ID 仍需迁移数据格式与行为。不同命名空间下同名路径不能直接归并；最终映射键应为“注册表类型 + 原命名空间 + 原路径”。显式改名/合并必须在映射台账登记规则与资源引用变换，不做全文替换或按中文名匹配。

最终单 Mod 携带旧命名空间的注册、资源加载、翻译、结构解析与打包行为须在基础阶段实测，当前是建议方案。

## 三份互补台账

| 台账 | 主键与内容 | 防止的问题 |
| --- | --- | --- |
| 内容映射 | 注册表 + 旧 ID → 新 ID/内部表示、所有者、来源文件 | 漏项、重名、误删、重复注册 |
| 行为对齐 | 稳定功能 ID → 入口/条件/成本/结果/失败/消费者、公式、调用证据 | 将静态注册当作完整功能、只迁移成功分支 |
| 验收证据 | 功能 ID + 版本/场景 → 构建/服务端/客户端/旧版对照结果与证据 | 混淆写了代码、跑过测试和玩家体验通过 |

这些台账共享 ID，不复制数值正文。模块完成度同时显示“内容映射覆盖”“行为闭环覆盖”“实际验收覆盖”，禁止混成一个含糊百分比。所有原始条目保留处理结果；未裁定项明确计入未完成。

当前工具只生成第一类的来源半边与文件证据，尚未分配新 ID、模块归属或行为状态。后续按系统丰富台账，不自动用文件名推断功能已覆盖。

## 定义、实例和执行

- 常量、配方、商品池、词条、功法属性和技能参数按系统定义结构化表达。旧超长分隔字符串先按原解析语义解码，保留顺序、重复项、缺省值和数值单位，再转换为目标格式。
- 定义只描述规则参数；动态行为由 Java 服务/有限的明确执行器实现。首期不造通用脚本语言或一个解释全部 Procedure 的引擎。
- 旧装备、法宝、丹药、书籍 NBT 按所有者转换为类型化组件。字段拼写可在导入适配中识别，正式域模型不沿用含糊拼写。
- 一般合成、熔炼、掉落、标签与世界数据优先使用目标版本已有数据机制；专用鼎炉、阵法和银行保留业务服务。不要把需要状态机的生产硬塞进无状态配方。
- 同类实体共享确实相同的基础行为；不同 Boss、特殊妖兽和技能保留显式策略，避免一个巨大 `switch(id)` 或为每个编号复制整套 AI。

## 数值迁移

每条公式记录：输入与单位、有效范围、运算顺序、整数/浮点规则、截断位置、随机分布与抽样次数、边界条件、调用入口、消费者及至少一组手算/旧运行算例。领域模型可以更清晰，但计算语义必须等价。

不把所有旧 double 无条件换为 int/long。余额等离散整数在明确取整规则后可采用有溢出检查的整数单位；五行、倍率和连续属性按旧精度核对。GUI 中展示的小数位不代表服务端采用相同精度。

炼器预览与实作若旧版确实不同，先保留两种政策的证据，再裁定。推荐共享输入解析与公式实现，通过明确的预览/执行语义决定输出，避免复制代码；不能在架构阶段私自宣告数值已统一。

## 菜单与表现

旧菜单先按“入口、槽位、按钮、条件、输入输出、关闭行为”登记，不用屏幕数量代替功能数量。HUD、覆盖层、按键、Tooltip 和普通交互另列，不能只盘点 MenuType。

本轮不设计具体 UI 布局；之后优先保持旧操作能力和视觉识别，逐项确定允许改进。客户端 UI 库不拥有玩法存档、公式或扣费逻辑。所有按钮接入相同的服务端命令入口；中文文案只表达玩法信息。

资产核对覆盖模型父链、纹理、blockstate 全状态、动画、音效、粒子、翻译与字体；持物/落地/背包/方块世界表现分别验收。实体类型清单区分本体、形态、弹体和纯视觉实体，不能把实体总量当作妖兽种数。

世界内容核对覆盖全部旧维度、群系、结构 NBT、出生/自然生成、矿物/药草/材料供给、宝箱与商店、传送回程。自然获取线路未接通时，不能因为命令可生成物品而标记玩法完成。

## 来源与可移交性

当前引用旧工程的本机只读路径，已生成清单有 SHA-256 以识别来源变化；没有复制整套旧工程进新目录。协作者需要提供相同来源，并使用提取工具的 `--source-workspace` 参数定位。

发布前收集每类第三方资产、库与两旧工程许可证、署名和来源；旧 `mods.toml` 的许可证声明不能替代逐资产来源核对。来源归 `docs/licenses`，不从当前项目许可证字段推导所有资产可重许可。
