# 开发规则

## 对“GPT 防御编程”的调查与本项目要求

2026-11-01 按负责人要求检索了中文讨论与公开的代码清理规则。“GPT 防御编程”在这些来源中是对 AI 代码冗余的批评用语，没有发现统一的正式规范。公开的 `deslop` 文本具体批评：对可信路径反复判空、无必要的 try/catch、为了绕过类型问题使用强制转换，以及和所在项目不一致的注释/样板。

来源为讨论与作者发布的规则文本，只用于解释该说法，不作为本项目自动执行的技能或额外批准流程：

- [作者公开的 deslop 文本](https://gist.github.com/prathamdby/587473fb7b80a2426aab375e463001c4)，列举不符合实际信任边界的防御检查、过量注释和类型绕过。

中文检索也返回讨论帖，但本轮没有可复核的完整正文；不把搜索摘要扩写成行业共识。上述原作者文本已直接读取。它说明一种具体批评，不证明传统防御性编程本身没有价值。

本项目遵守用户已明确提出的要求：直接实现已确定规则；不增加猜测性的兜底、兼容、重试和测试。必要外部输入处理由真实入口承担，内部方法按照已定义的类型和调用约束工作。

负责人2026-11-07再次强调：移植先核对1.18.2版本的实际代码与调用链，没有必要不新增Test。已有足够源码依据的规则直接移植；编译、加载和关键路径实机按实际风险选择，不为每批建立专项脚本，也不把反复修检查脚本当作玩法进展。

## 实施规则

| 情况 | 本项目处理 |
| --- | --- |
| 已由菜单、构造器或类型约束保证的数据 | 内部直接使用，不重复多层判空/范围检查 |
| 数据包缺字段、引用错误或数值无法解析 | 在加载入口报告具体错误；不返回空配方、0 数值或默认装备掩盖问题 |
| 客户端菜单/施法请求 | 验证当前玩家、实际菜单/装置及操作条件；这是权威边界，不是给所有方法套防御模板 |
| 调用失败 | 按真实错误处理；禁止空 catch、捕获 Exception 后继续成功流程 |
| 兼容需求 | 只实现已批准且有实际数据格式的转换；不预建多版本回退和猜测性字段别名 |
| 重复/异步操作 | 根据当前炉次、任务、菜单状态处理；有真实异步/重试需求再设计，不给普通 tick 加通用重试平台 |
| 抽象 | 先用具体类型和方法；实际共享后提取；不强制 interface/factory/repository 层层对应 |
| 测试 | 只针对真实公式、跨端/保存边界、共享逻辑与可复现错误；验证方式选择见移植技能的[验证参考](../../.claude/skills/minecraft-mod-porting/references/verification.md) |

不写 `assert true`、仅验证常量/注册非空的套件、把实现公式复制一遍的 expected，也不为纯文本/资源调整制造测试代码。

## 正式代码与文档

Java 显式 import、简类名、无通配符；有真实同名冲突才使用限定名。文本 UTF-8。关键中文注释说明公式、数据所有者、生命周期、客户端与服务端关系；不写逐行翻译、调试经过和“以后便于扩展”的口号。

修改后检查本轮代码的导入、无用方法、复制残留、重复逻辑和注释真实性。编译成功不能代替代码审阅。Tooltip 只展示背景、操作、效果及必要数值；实现限制与核对记录留在开发文档。

未经确认的来源行为不包装成“优化”；发现问题写入所属正文，按批准范围处理。
