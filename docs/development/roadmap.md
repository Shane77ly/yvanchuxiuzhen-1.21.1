# 全量实施与验收顺序

本路线覆盖两个 1.18.2 Mod 的全部范围。各批次完成整个所属系统及其内容，不把抽样功能作为交付范围。技术检查可以先定位某个 API 问题，但抽样通过不能抵消剩余内容。

当前执行 A。负责人 2026-11-02 授权先建立开发环境（B 中“锁定构建依赖”的基础构建部分，见[架构](architecture.md)“技术依赖”）；B 的其余内容与 C～I 未启动。架构未批准；没有 goal 任务。

## 批次和出口

| 批次 | 完整工作包 | 前置 | 本批完成依据 |
| --- | --- | --- | --- |
| A 调查和方案 | 来源身份、全部注册/文件/状态/过程/编辑器图索引、关键调用链、19 系统正文、公共入口与依赖、编号 Excel、待裁定问题和开发文档 | 两个参考工程 | 提案可追踪到源码；负责人明确批准架构与范围后才能进入实现 |
| B 工程与内容基础 | 锁定构建依赖；全部注册分类与 ID 映射；资源格式迁移；附件/组件/菜单/网络接入；公共数据定义加载 | A 批准 | 客户端和专用服务器启动；资源/引用可定位；没有把占位行为计为完成 |
| C 玩家与战斗 | 完整成长、出生/体质/金丹/元婴/轮回、全部功法、属性、战斗/状态/关系、技能/移动、装备与本命系统 | B | 每条玩法和数值表有入口及消费者；保存/死亡/重登与目标事件阶段验证 |
| D 材料和生产 | 全部材料与采集、炼器/升级/修理、炼丹/分合丹/药理、符箓制作和全部效果、生活生产及容器 | B、C 所需契约 | 全部输入/产物去向、职业进度、失败与装置生命周期完成 |
| E 世界和生物 | 全部维度/群系/结构/资源投放、城镇/副本/传送；全部生物族、AI、形态、采集、驯养、蛊虫/傀儡相关行为 | B、C、D 的定义与效果 | 生存获取链闭合；模型/动画/体型/伤害/掉落与实际运行记录对应 |
| F NPC、经济、任务 | 全部对话/商店/价格表、货币/银行、现场拍卖、悬赏和任务、管理编辑入口 | C～E 的实际消费者 | 获取、消费、扣款、发奖和推进均接通；现场多人交互与保存恢复核对 |
| G 阵法和后期联动 | 所有阵位/材料/技能分支、阵旗、供能、感应/红石/遥控、跨维度；跨系统特殊功法和后期效果 | C～F | 每个分支都有实际消费者与反馈；源码断链按已批准取舍完成 |
| H 界面与表现终核 | 92 个菜单对应功能、额外 HUD/覆盖层/按键、文案、实体和物品渲染、动画/粒子/声音、管理面板 | 所有系统 | 操作与表现逐项确认；技术成功和视觉认可分别登记 |
| I 完整对照与发布 | 全量台账收口；1.18.2 与 1.21.1 对照；专用服务器/多人/性能场景；许可证与交付文档 | B～H | 所有条目有处理结果；所有批准范围内行为验收完成；发布仍按负责人授权 |

界面、实体表现和资源在所属系统实施时同步接入，H 是最终全量复核。E 的世界基础可与 D 按无依赖的内容交错推进，F/G 的问题调查从 A 开始，不留到实现末尾才发现。

## 系统工作单与验证

每个系统使用同一份正文和台账，按[移植技能](../../.claude/skills/minecraft-mod-porting/SKILL.md)的“系统工作单”推进，验证方式按[验证参考](../../.claude/skills/minecraft-mod-porting/references/verification.md)选择。本项目的登记位置为系统 README 状态、设计/架构/数值正文和月度记录。

## goal 启动条件

负责人明确批准提案并明确要求启动后，才创建 goal；届时目标必须引用批准版本、完整范围、裁定结果和完成条件。当前方案中的待裁定项不能自动视为批准，也不能在 goal 中静默缩减内容。无需为了准备提案创建或运行 goal。

本轮状态与检查结果见 [项目状态](../systems/project/README.md)。
